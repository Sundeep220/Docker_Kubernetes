# 🟦 **📌 1. Helm Chart Structure (Full Overview)**

When you create a chart:

```
helm create myapp
```

Helm generates this:

```
myapp/
├── Chart.yaml
├── values.yaml
├── charts/
├── templates/
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── ingress.yaml
│   ├── _helpers.tpl
│   ├── hpa.yaml
│   ├── serviceaccount.yaml
│   └── tests/
│       └── test-connection.yaml
└── .helmignore
```

Let’s understand each component in depth.

---

# 🟥 **📌 2. Chart.yaml (Metadata about the chart)**

This file describes WHAT this chart is.

Example:

```yaml
apiVersion: v2
name: myapp
description: A Helm chart for Kubernetes
type: application
version: 0.1.0
appVersion: "1.0"
```

### 📌 Fields meaning:

* **name** → Chart name
* **version** → Chart version
* **appVersion** → Version of the app you are deploying
* **description** → Free text
* **type** → application or library
* **dependencies** → subcharts

💡 `Chart.yaml` = package.json / pom.xml of Helm.

---

# 🟩 **📌 3. values.yaml (Default values for the chart)**

This is the **default config** for your chart.

Example:

```yaml
replicaCount: 2

image:
  repository: myapp-image
  tag: "1.0"
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 80
```

Purpose:

* Stores config variables
* Passed to templates with `.Values`
* Easily overridden with `-f` or `--set`

💡 Think of it as **global variables** for your templates.

---

# 🟧 **📌 4. templates/ directory (the heart of the chart)**

All Kubernetes manifests go here — but with templating.

Inside templates:

```
deployment.yaml
service.yaml
ingress.yaml
configmap.yaml
secret.yaml
serviceaccount.yaml
hpa.yaml
_notes.tpl (for NOTE messages)
_helpers.tpl (helper macros)
tests/test-connection.yaml
```

Helm takes everything inside `templates/`, renders templates, and sends to Kubernetes.

Let’s explore subcomponents.

---

# 🟨 **📌 4.1 deployment.yaml (Core Deployment manifest)**

Example (generated by Helm):

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "myapp.fullname" . }}
spec:
  replicas: {{ .Values.replicaCount }}
  template:
    spec:
      containers:
        - name: myapp
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
```

Key concepts:

* uses `.Values`
* uses `include` to reference helpers
* is fully templated

---

# 🟧 **📌 4.2 service.yaml**

Same idea:

```yaml
kind: Service
spec:
  type: {{ .Values.service.type }}
  ports:
    - port: {{ .Values.service.port }}
```

# 🟫 **📌 4.6 _helpers.tpl (Template helper functions)**

This is VERY important.

Example:

```yaml
{{- define "myapp.fullname" -}}
{{ .Release.Name }}-{{ .Chart.Name }}
{{- end -}}
```

Now usage:

```yaml
metadata:
  name: {{ include "myapp.fullname" . }}
```

Benefits:

* DRY (don’t repeat yourself)
* Reusable snippets
* Standard naming patterns

💡 This is one of the most powerful parts of Helm.

# 🟧 **📌 4.7 tests/ folder**

Contains test manifests.

Example:

```
apiVersion: v1
kind: Pod
metadata:
  annotations:
    "helm.sh/hook": test
```

Run with:

```
helm test myapp
```

---

# 🟥 **📌 5. charts/ directory (Dependencies)**

If your Chart.yaml contains something like:

```yaml
dependencies:
  - name: redis
    version: 14.8.8
    repository: https://charts.bitnami.com/bitnami
```

Helm downloads the Redis chart into the `charts/` folder.

This is used for:

* redis
* mysql
* kafka
* mongodb
* etc.

💡 charts/ = vendor/ or node_modules/ for Helm.

---

# 🟪 **📌 6. .helmignore**

Similar to `.gitignore`.

Contains patterns of files to ignore when packaging the chart.

Example:

```
*.md
*.txt
test/
charts/
```

Helm excludes these when creating `.tgz` packages.

---

# 🟧 **📌 7. Additional Important Files Helm Might Add**

## 🟫 NOTES.txt

Inside templates:

```
templates/NOTES.txt
```

After installation, Helm prints this as a user guide.

Example:

```
Your application is deployed!
Run: kubectl get pods -n {{ .Release.Namespace }}
```

---

# 🟦 **📌 8. How Helm uses this Structure Internally**

1️⃣ Read **Chart.yaml**
2️⃣ Load **values.yaml**
3️⃣ Merge with any overrides
4️⃣ Render **templates/** using Go templates
5️⃣ Generate final Kubernetes YAML
6️⃣ Apply to cluster
7️⃣ Save release info for rollback

---

# 🟩 **📌 9. Minimal Helm Chart (Key files only)**

At minimum, a chart needs:

```
Chart.yaml
values.yaml
templates/
    deployment.yaml
```

Everything else is optional.

# 🎯 **Summary of Helm Chart Structure**

| File / Directory | Purpose                                 |
| ---------------- | --------------------------------------- |
| **Chart.yaml**   | Metadata, name, version                 |
| **values.yaml**  | Default config values                   |
| **templates/**   | Actual Kubernetes manifests (templated) |
| **_helpers.tpl** | Named templates for reuse               |
| **NOTES.txt**    | Output after installation               |
| **charts/**      | Subcharts (dependencies)                |
| **tests/**       | Test pods for helm test                 |
| **.helmignore**  | Files ignored in packaging              |
